# UX & Conformity Audit — Transactions · Budgets · Dashboard/Reports

> **Scope:** the 3 key pages plus their modals, tables, filter bars, widgets, and the surrounding layout/navigation.
> **Method:** read-only review of source against `docs/specs/` and the API contracts mapped in the architecture step. This is a _photograph of the current state_ — no solutions, no code.
> **Reminder:** every page is still on mock data + local state (see architecture map). Findings below are about the **built frontend experience**, independent of the data-wiring gap, except where the two interact (money types, dead controls).

## Severity legend

- **Blocking** — breaks a core task, makes a feature unusable, or fails WCAG AA in a way that excludes users.
- **Major** — spec/functional gap, misleading feedback, or a real finance-correctness risk a user would hit.
- **Minor** — polish, consistency, or a smaller heuristic miss.

## Prioritized synthesis (impact-ordered)

**Tier 0 — Blocking, fix before any reconnection demo**

1. **T1 — Edit transaction shows an empty form** (silent data loss). The single most dangerous interaction bug.
2. **C1 — Nested `<main>`** and **T5 — keyboard/touch-inaccessible row actions** and **T6 — unlabeled date inputs** (WCAG AA exclusions; cheap to fix).

**Tier 1 — Major functional/conformity gaps that make features feel broken** 3. **Dead controls that lie to the user:** R1 (report filters), B2 (budget period), B1 (budget type filter), T3 (import), R2 (export). These are the loudest "it doesn't work" signals. 4. **D1 (duplicate widget)** + **D2 (period selector updates only 2 widgets)** — the dashboard's first impression looks broken/misleading. 5. **Silent data-corruption traps surfacing at wire-up:** B3 (category dropped on edit), B5 (locale date parsing), T2 (category not required), B4 (end date optional).

**Tier 2 — Finance-correctness & coherence (mostly bite at integration)** 6. **Money-as-float across the board** (T8, B6) — must be settled together with the string/`numeric` contract. 7. **C2 — divergent mock vocabularies** — resolves naturally when real `categories`/`labels` arrive, but worth deciding now. 8. **T4 (transfer destination hidden), D3 (no Net), C3 (no error states), C6 (unused loading)** — completeness of the core experience.

**Tier 3 — Polish:** T9, T10, B8, R3, R4, R5, C4, C5, C7.

**Theme:** the component library is genuinely good — state-aware widgets, correct colour/sign conventions, solid empty states, accessible dialogs. The damage is concentrated in (a) **broken or absent affordances** (dead filters/buttons, missing import), (b) **two real interaction bugs** (T1, B3), (c) a **systemic absence of error/loading wiring**, and (d) **float money + fragile dates** that will detonate at integration. Most Tier-0/1 items are small, localized fixes — not redesigns.
